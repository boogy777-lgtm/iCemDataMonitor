## 1. DCOM repair / trusted preservation — FAIL

- На прежнем Runtime [42825399418](https://github.com/boogy777-lgtm/iCemDataMonitor/actions/runs/42825399418), head `12b94a8`, шесть случаев прошли, `descriptor-repair` потерял четыре настроенных логических Access/Launch REG_BINARY values двух AppID после `/fomus`. Snapshot evidence: parent `rust/target/opc-acceptance-42825399418/opc-runtime-descriptor-repair-evidence/`. Это настоящий FAIL, не comparator error.
- Synthetic first-sequence probe 14/14 (`rust/target/opc-reglocator-first-d9a8c61052494b81b58e45805c813f1c/` в parent) показывает лишь transport, не доверенный elevated guard и не реальный Runtime. Raw binary — `#x<hex>`; `SecureCustomProperties` разрешает перенос данных, но не удостоверяет их источник.
- Дополнительная security-граница: [Microsoft: immediate custom actions impersonate user](https://devblogs.microsoft.com/setup/immediate-custom-actions-always-impersonate/), [custom action security](https://learn.microsoft.com/en-us/windows/win32/msi/custom-action-security) и [deferred execution](https://learn.microsoft.com/en-us/windows/win32/msi/deferred-execution-custom-actions). Immediate EXE в execute sequence не становится доверенным только потому, что он в server sequence; non-impersonated deferred action запускается после `InstallInitialize`. Наивное сравнение пользовательским EXE или переносом `SecureCustomProperties` не принято как защита. Нужна доказанная архитектура доверенного read-only сравнения **до транзакции**, затем точная передача значений и реальная семикейсовая матрица/UI/injection/type/`/fomus`/`/famus`/x86+x64 tests. Код исправления Runtime в этой ветке ещё не написан.
- Read-only проверка VM: OpcEnum service `C:\Windows\SysWOW64\OPCEnum.exe`, Manual, LocalSystem; первый AppID присутствует с binary Access/Launch в обеих views, второй отсутствует в обеих. Значения не выводились и не менялись. Microsoft документирует `HKLM\SOFTWARE\Classes\AppID` как shared для Windows 7 и новее; обе logical views всё равно необходимо проверять.
