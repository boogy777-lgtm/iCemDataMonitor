## 4. UX integration / genuine Release Setup — FAIL

- Штатный `--autostart` выбирает соседний `icem-opc-da-sidecar.exe` как профиль DA, если явно не задан `--opc-da-config`; dev/fixture запуск без `--autostart` не получает новый профиль. Существующий `opcda_on=0` по-прежнему запрещает автоматический запуск, `1` инициирует реальный owner path; явный CLI-профиль имеет приоритет. Прежний **fail-fast сохраняется**: ошибка включённого DA блокирует готовность Host и остальных служб. Установка/постоянная регистрация COM, DCOM и чужих компонентов этим не меняются; работающий sidecar регистрирует собственную runtime class. Process tests изолируют Host от настоящего sidecar: один проверяет отсутствие файла и реальный loopback UA при DA OFF, второй — ON/OFF и отсутствие повторов с **test-only IPC peer без COM**. Оба проверяют неизменность INI; **фактический Windows COM/client acceptance этим не доказан**. Результаты тестов принадлежат только проверенному head, см. PR/итог прохода.
- Переход к независимому non-fatal DA startup пока небезопасен: прежний `opc_da_consumer/mod.rs` после неудачного handshake игнорирует результат `handle.stop`, поэтому завершение собственного child/worker при ошибке очистки не доказано. Нужно сохранить owner для явной последующей остановки, включая ошибки создания потоков и переполнение registry, и проверить fault injection; простое подавление ошибки расширило бы риск неуправляемого процесса. До этого требуется UI/Host recovery и изоляция остальных служб; fail-fast не объявляется завершением задачи.
- Уточнение требования из ранее зафиксированного WIP `PROTOCOL_DEFAULTS_2026-11-10.ru.md:22–26`: ошибка **штатного** default сервера должна быть видна в статусе/логе и не блокировать остальные службы и GUI; явные CLI-конфиги сохраняют fail-fast. Следующий инкремент должен реализовать это с retained ownership и fault injection, не копируя WIP вслепую; текущий fail-fast остаётся незакрытым ограничением.
- `6891b62`: новый `opcda_on=1`; явный `opcda_on=0` в существующем INI сохраняется и запрещает автоматический старт **сконфигурированного** собственного DA sidecar. Ручной start остаётся отдельной операцией. Тесты Rust config ниже; host-side regression добавлен, но полный Windows host build/test ещё не подтверждён. Настройки без sidecar config не доказывают реально работающий DA.
