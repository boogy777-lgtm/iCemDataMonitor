# Host tray: диагностика 2026-11-09

## Подтверждённая причина дефекта

`apps/host/src/cli.rs` определял CLI по наличию ключевого слова в любом
аргументе. Например, `--ini stop` ошибочно выполнял команду остановки вместо
запуска Host с указанным файлом; аналогично `restart`, `header`, `snapshot`,
`get` и `--start` в значениях опций перехватывали запуск до создания tray.
Теперь CLI определяется первым аргументом, как и грамматика поддерживаемых
команд, в том числе с первым `--start`. Regression проверяет все ключевые слова
в значении `--ini` и вход в CLI по каждой команде без обращений к IPC.

Это подтверждённая причина отдельного класса ошибок, но не причина наблюдаемого
отсутствия значка в конкретной пользовательской установке.

## Наблюдение пользовательского сценария

При read-only осмотре работал установленный `icem-shell-dev.exe` без аргументов,
но Rust Host среди процессов отсутствовал. Публичный desktop shortcut указывает
на этот Shell без аргументов; пользовательский shortcut с тем же названием
указывает на старый `iCemDataMonitor.WinUI.exe`. Shell запускает Host с
`--autostart` через `Launch::installed`, не с одним `--station-config`.
Рядом с установленным Host обнаружен штатный ICO. Никакие процессы не завершались.

Изолированная копия установленного Host (отдельные PROGRAMDATA, pipe, INI,
loopback-порты и имя EXE) с `--station-config ... --autostart` при отсутствии
INI воспроизвела Windows error 32 при создании config.ini до старта tray.
При заранее созданном валидном изолированном INI та же копия дошла до вывода
`Consumers` и завершилась в пределах 15 секунд при `--duration-ms 5000` (код
выхода через использованный `Start-Process` не получен); к установленному MMF
не обращалась. Это подтверждает причину ошибки первого запуска, независимо
также установленную агентом A; исправление config принадлежит ему. Отображение
значка в Explorer этим запуском не подтверждено.

Команда tray «Открыть панель» теперь передаёт Shell только Host pipe. Shell
получает фактически связанный HTTP endpoint через Host, не принуждается к
сконструированному URL. Команда «Открыть Web» не изменена. Реализация endpoint
discovery и её тестирование принадлежат агенту D и объединённой проверке.

Аудит `gpui-tray 0.1.4`: Windows backend владеет `HICON`, HWND и регистрацией
`Shell_NotifyIconW(NIM_ADD)`; `Tray::build` возвращает ошибку при неуспехе.
Host держит `Tray` в async-задаче до `close`, ошибки refresh завершают worker и
отражаются через отключение канала. При рестарте Explorer backend повторяет
`NIM_ADD`, но ошибку этой повторной регистрации игнорирует; визуальная проверка
этого сценария не проводилась.

## Диагностика штатного запуска

Без аргументов, `--autostart`, `--ini` и `--port` включают штатный autostart:
без ограничения времени, с иконкой `assets/iCemDataMonitor.ico` рядом с EXE.
Отсутствие файла или ошибка настройки останавливают запуск с диагностикой;
подстановка фиктивной иконки и исправление пользовательских настроек не выполнялись.
Development `--station-config` без `--autostart` сам по себе не включает tray
и ограничен 10 секундами, если явно не переданы соответствующие параметры.
Создание tray происходит после запуска слоёв, Web и local RPC; ошибка до этого
этапа тоже не является доказательством неисправности Explorer.

## Проверки и границы

`cargo fmt --package icem-host-app -- --check` — PASS на Windows.
Целевой `cargo test --release --locked --offline -p icem-host-app --bin
icem-host-dev host_option_values_do_not_trigger_cli_dispatch` — PASS (1 тест).
Добавлен Windows regression `host_tray_owns_icon_until_explicit_stop`: проверяет
ошибку отсутствующего ICO, фактический `NIM_ADD`, канал и явное закрытие;
запуск заблокирован ошибкой компиляции промежуточного параллельного изменения
агента A: `icem-config/src/station.rs` ссылается на ещё не подключённый
`icem_windows_native` (E0433); сам тест не выполнялся. Нужен повтор после
завершения изменений A. Агент A сообщил, что исправление завершено и его
фокусные тесты прошли; повтор tray-теста и проверка последней правки запуска
панели ожидают общего последовательного прогона родителя. Новых сборок не
запускалось. `cargo fmt --package icem-desktop -- --check` — PASS до последней
правки Host. Общую Release-проверку
выполняет родитель. Установленные конфигурации и процессы не изменялись.
Реальная проверка значка в области уведомлений, меню, Explorer restart,
пользовательского запуска и визуальная/operator-приёмка остаются открытыми.
